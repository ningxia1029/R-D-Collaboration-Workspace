## 1. 产品定义

产品定位为 **PLM 企业研发智能体（R&D Copilot）**：它是 WorkBuddy Pro 上方的自然语言业务入口，不是独立 PLM，也不是把通用聊天框接到数据库。

智能体负责理解用户意图、调用受控 PLM Tool、组合结构化业务数据与有权限的工程文档，并给出带来源、权限范围和数据时间的回答。WorkBuddy Pro 继续作为项目、任务、BOM、技术参数、ECR/ECO、知识库、用户权限和审计记录的唯一事实源。

首期要回答三类问题：

1. **项目事实**：项目进度、延期任务、阻塞链、里程碑、BOM 风险、ECR/ECO 影响。
2. **研发资源**：成员任务量和工时；组织架构与部门负载在补齐组织及产能数据后开放。
3. **工程知识**：在用户可见范围内检索规范、调试记录、失效分析和历史经验，并引用具体文档版本。

## 2. 当前基线与缺口

基线依据：[README](../README.md)、[Prisma 数据模型](../prisma/schema.prisma)、[RBAC](../src/lib/rbac.ts)、[Dashboard 聚合](../src/lib/services/dashboardService.ts)、[搜索服务](../src/lib/services/searchService.ts) 和 [生产验收清单](./ACCEPTANCE_CHECKLIST.md)。

| 领域 | 当前已具备 | 智能体上线前的关键缺口 |
|---|---|---|
| 项目与任务 | 项目、WBS、任务状态、负责人、日期、依赖、里程碑、工时 | 进度目前按 `Done 任务数 / 总任务数` 计算，缺少权重、任务完成百分比和算法版本说明 |
| PLM | 产品/BOM、物料、技术参数、ECR/ECO、影响项、审批与审计 | 需形成面向智能体的稳定只读聚合接口和证据对象 |
| 权限 | 登录态、全局 RBAC、项目成员角色覆盖、实体归属校验 | Agent Tool 必须复用同一权限链；不得信任模型传入的用户、角色或项目范围 |
| 知识库 | Markdown 文档、版本、标签、项目范围过滤、PostgreSQL 关键词搜索 | 尚无分块、向量/混合检索、引用定位、检索评测和文档提示注入防护 |
| 人员组织 | 用户、角色、项目成员关系 | 没有部门树、岗位、汇报关系和组织范围权限，暂不能可信回答“算法组谁最忙” |
| 资源负载 | 未完成任务预估工时、累计登记工时、开放任务数 | 没有时间窗、标准产能、请假/日历、分时计划；不能把现有统计直接解释为利用率 |
| 活动与报告 | 通用 `AuditLog`、部分业务状态记录 | 缺少统一关联 ID、项目维度、结构化活动类型和可重复生成的周报数据快照 |
| Agent 治理 | 无 | 需新增运行、Tool 调用、审批、反馈、模型版本、耗时和成本审计 |
| 生产基础 | 已有生产加固方案与预验收记录 | 依赖漏洞、隔离数据库迁移/恢复、浏览器 RBAC 矩阵及桌面业务验收仍是上线前置门禁 |

## 3. 目标与非目标

### 3.1 产品目标

- 用户能用业务语言查询自己有权访问的研发数据，不需要理解数据库结构或 API。
- 数字、状态和实体关系来自确定性 Tool；文档结论来自权限过滤后的检索结果。
- 每个业务结论都能展示证据、跳转原实体，并标注 `asOf` 数据时间和计算口径。
- 无数据、数据质量不足或问题有歧义时明确说明，不猜测、不补造。
- 首期保持只读；后续写操作必须经过“提议—复核—人工确认—执行—回读验证—审计”。
- Agent 可观测、可评测、可停用、可回放，模型供应商可替换。

### 3.2 非目标

- 不替代 WorkBuddy Pro 的业务页面、审批流、RBAC 或审计系统。
- 不允许模型直接执行 SQL、拼接 Prisma 查询或绕过应用服务访问数据库。
- 不把项目、任务、BOM 等结构化主数据整体复制到向量数据库。
- 首期不建设多 Agent 团队、自主长期执行、自动审批或自动发布。
- 首期不开放删除、批量导入、ECR/ECO 审批、产品发布等高风险动作。
- 不以 Dify、RAGFlow 或通用编码 Agent 作为 PLM 核心事实源。

## 4. 目标用户与权限预期

| 用户 | 核心诉求 | 默认可见范围 |
|---|---|---|
| 研发工程师 | 我的任务、阻塞原因、相关 BOM/ECO、工程知识 | 本人所属项目；仅本人可见的资源信息不得扩散 |
| 项目经理 | 项目进度、延期、风险、成员负载、周报草稿 | 其管理或加入的项目；团队工时需 `time:read_all` |
| 研发负责人 | 跨项目健康度、部门负载、资源冲突 | 经授权的组织单元与项目交集；该范围需新增组织权限 |
| PLM/系统管理员 | 配置 Tool、模型、审计、评测和停用开关 | 管理权限不等于默认把全部敏感数据发送给模型 |
| 访客/只读人员 | 查询已授权的项目事实和知识 | 当前项目成员范围，禁止跨项目推断 |

任何回答范围均取“当前登录用户权限 ∩ Tool 所需权限 ∩ 实体所属项目/组织范围”，而不是由提示词决定。

## 5. 首期核心场景

### P0：只读业务问答

| 编号 | 示例问题 | 预期输出 |
|---|---|---|
| UC-01 | “A 项目现在进度多少？” | 项目解析结果、完成率、算法口径、完成/总任务数、数据时间、项目链接 |
| UC-02 | “未来两周有哪些会延期的任务？” | 未完成且到期/即将到期的任务、负责人、前置依赖、风险原因 |
| UC-03 | “这个项目为什么是红灯？” | 阻塞任务、逾期任务、延迟 BOM 的数量及可追溯实体 |
| UC-04 | “DVT 里程碑前还有哪些关键事项？” | 里程碑、P0/P1 未完成任务、依赖和关键物料风险 |
| UC-05 | “ECO-2026-xxx 会影响什么？” | 变更状态、影响对象、关联任务/BOM/规格和审批记录 |
| UC-06 | “找一下相机模组失效分析” | 仅返回用户可见文档，附文档版本、片段和链接 |
| UC-07 | “给我生成本周项目周报草稿” | 结构化事实汇总、风险、完成事项、下周节点、引用；明确其为草稿 |

### P1：组织与资源洞察

在组织树、组织权限、产能和时间窗数据完成后开放：

- “算法组本周谁负载最高？”
- “未来四周哪些成员可能超负荷？”
- “两个项目是否在争用同一个关键成员？”

输出必须同时给出时间范围、计算方法、产能基线、数据质量和缺失项。只有开放任务总量时，只能称为“开放任务/预估工时排序”，不能称为“利用率”。

### P2：受控业务动作

后续可从低风险动作开始，例如生成任务更新草稿或周报草稿。真正写入 PLM 前必须由用户在结构化确认页中检查目标、字段差异和风险；高风险动作继续只允许在原业务页面完成。

## 6. 用户体验要求

### 6.1 入口与上下文

- 在工作台提供独立智能体页面，并允许项目页以侧边栏方式携带当前 `projectId`。
- 用户可显式切换“当前项目/全部可见项目”；Agent 不得仅凭项目名称静默选中歧义对象。
- 名称命中多个项目、物料或变更时，只展示有权限的候选项并要求用户选择。
- 会话上下文只用于省略表达解析；任何实体访问仍需每次重新鉴权。

### 6.2 标准回答结构

1. **结论**：直接回答问题。
2. **关键指标/风险**：结构化列出数字和状态。
3. **依据**：实体或文档引用，可跳转至 WorkBuddy Pro。
4. **数据口径**：`asOf`、筛选时间窗、进度或负载算法。
5. **限制**：缺失字段、低置信数据或未覆盖范围。

以下情况不得生成貌似确定的答案：

- 没有匹配数据；
- 只有同名歧义对象；
- Tool 返回权限拒绝；
- 依赖服务失败或数据超出新鲜度要求；
- 文档片段不足以支撑结论；
- 负载缺少产能或时间分配数据。

## 7. 功能需求

### 7.1 会话与意图

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-001 | 使用 WorkBuddy 当前登录态创建 Agent Run，停用或降权必须在下一次 Tool 调用生效 | P0 |
| FR-002 | 支持流式回答、取消运行、超时提示和安全重试 | P0 |
| FR-003 | 支持项目/实体歧义消解，不允许模型猜测 ID | P0 |
| FR-004 | 保存会话前应用企业保留策略；管理员可关闭内容留存但保留最小审计 | P1 |

### 7.2 结构化数据 Tool

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-010 | 通过稳定、版本化、Schema 校验的 Tool 查询项目、任务、依赖、里程碑、BOM 和变更 | P0 |
| FR-011 | 每次 Tool 调用在服务端注入用户身份并执行实体级鉴权 | P0 |
| FR-012 | 聚合结果返回证据列表、数据时间、权限裁剪和计算口径 | P0 |
| FR-013 | 列表 Tool 使用有界分页、固定排序和最大时间范围，禁止无界扫描 | P0 |
| FR-014 | 组织、成员和负载 Tool 在数据模型与权限完成前保持禁用 | P0 |

详细输入输出见 [PLM Tool Contract v1](./PLM_TOOL_CONTRACT_V1.md)。

### 7.3 工程知识检索

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-020 | 检索前应用公共文档与项目文档可见范围，检索后再次校验实体权限 | P0 |
| FR-021 | 首版可使用现有关键词检索，但返回准确文档版本和片段位置 | P0 |
| FR-022 | 语料规模与评测证明需要后，再增加分块、向量或混合检索 | P1 |
| FR-023 | 文档内容视为不可信数据；其中的提示、命令或 Tool 指令不得改变系统策略 | P0 |
| FR-024 | 回答中的文档性结论必须引用实际检索片段；无片段不下结论 | P0 |

### 7.4 报告、反馈与治理

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-030 | 周报由确定性数据包驱动，正文标注“草稿”，每个主要结论可追溯 | P1 |
| FR-031 | 记录 Agent Run、模型、提示版本、Tool 调用、耗时、结果摘要、错误和证据 ID | P0 |
| FR-032 | 用户可对答案点赞/点踩、选择错误类型并补充说明 | P1 |
| FR-033 | 管理员可按用户、Tool、项目、模型和错误码查询审计，不默认展示敏感正文 | P1 |
| FR-034 | 支持全局停用 Agent、单 Tool 熔断和模型供应商切换 | P0 |

### 7.5 后续写操作约束

- 模型只能产生结构化变更提议，不直接调用最终执行接口。
- 确认页展示实体、当前版本、字段级 before/after、权限、风险和副作用。
- 执行前重新读取实体版本、用户状态、角色和权限；不一致则提议失效。
- 执行使用幂等键，成功后回读验证并写业务审计和 Agent 审计。
- 删除、批量导入、审批、生命周期发布、ECO 实施默认不进入首批动作范围。

## 8. AI-ready 数据要求

| 数据改造 | 建议设计 | 解锁能力 | 是否为只读 MVP 前置 |
|---|---|---|---|
| 进度口径 | v1 明确返回 `done_task_count`；后续评审是否新增任务权重与完成百分比 | 可解释项目进度 | 是，至少完成口径标识 |
| 组织结构 | `OrgUnit` 树、`Position`、用户主部门/岗位/经理、组织范围权限 | 部门与汇报链查询 | 否，对组织场景是前置 |
| 产能与时间窗 | 用户周标准产能；后续接入工作日历、请假和任务分时分配 | 可信负载与冲突分析 | 否，对负载场景是前置 |
| 活动数据 | 扩展 `AuditLog` 的 `projectId/correlationId/eventType/metadata`，必要时增加事务 Outbox | 周报、增量索引、回放 | 周报前置 |
| 文档证据 | 文档版本、分块 ID、标题层级/行区间、索引版本 | 精确引用与 RAG 评测 | 文档问答前置 |
| Agent 治理 | `AgentRun`、`AgentToolExecution`、`AgentApprovalRequest`、`AgentFeedback` | 审计、评测、动作审批 | 是，至少前两项 |

组织模型首版建议支持一个主部门与一条直接汇报线；跨职能协作继续使用 `ProjectMember`。若公司实际存在矩阵组织或一人多部门，应在建表前调整为带有效期的成员关系模型。

阶段 5 实现注记（2026-08-13）：文档版本片段与事务 Outbox 已落地；任务完成、ECR/ECO 流转和文档变更开始写入 `ActivityEvent`。历史活动不从当前快照回填，因此部署前的完成项/变更历史可能在周报中显示为省略。组织和负载数据仍未达到可用门槛。

## 9. 非功能要求

| 维度 | 评审目标 |
|---|---|
| 权限安全 | 权限矩阵中未授权数据泄露为 0；Tool 参数不得包含可由模型伪造的用户/角色/可见项目列表 |
| 可追溯性 | 业务数字和关键结论的证据覆盖率 100%；每次 Tool 调用均有 `runId/traceId/asOf` |
| 正确性 | 固定测试数据上，确定性聚合值与直接业务查询完全一致；无数据时不得编造 |
| 性能 | 简单问答（1–3 次 Tool）目标 P95 ≤ 8 秒；周报类目标 P95 ≤ 20 秒，均需在模型与部署确定后实测校准 |
| 可用性 | Tool 或模型异常时局部失败、可取消、可重试，不影响 PLM 主业务；不得无限 Agent 循环 |
| 隐私 | 发送给外部模型的数据最小化、可配置脱敏；模型供应商、数据驻留和保留策略需单独评审 |
| 可运营性 | 可按 Tool/模型/提示版本统计成功率、延迟、token/费用；阈值和告警在试点后确定 |
| 兼容性 | Tool Contract 向后兼容；破坏性变更使用新主版本并保持迁移期 |

## 10. 实施阶段与门禁

| 阶段 | 交付物 | 进入下一阶段的门禁 |
|---|---|---|
| Gate 0：产品基线 | 完成现有依赖、数据库恢复、RBAC 和桌面业务验收 | [生产验收清单](./ACCEPTANCE_CHECKLIST.md) 的 P0 阻断项关闭或形成书面风险接受 |
| Phase 1：AI-ready 数据 | 进度口径、Agent 审计、Tool Gateway 基础；组织/活动模型按已确认范围迁移 | Prisma 迁移在隔离库演练；权限与回滚测试通过 |
| Phase 2：只读 Agent MVP | 项目、任务、依赖、里程碑、BOM、变更 Tool；智能体 UI；证据与评测 | 安全矩阵、确定性答案、无数据和 Tool 审计验收通过 |
| Phase 3：知识与报告 | 权限感知文档证据、必要时混合检索、周报数据包 | 检索评测和提示注入测试达到已批准阈值 |
| Phase 4：组织与资源 | 组织树、组织授权、产能/负载问答 | 数据完整率和负载算法评审通过，不以缺失数据生成利用率 |
| Phase 5：受控动作 | 低风险提议、确认、幂等执行、回读验证 | 未确认写入为 0；并发版本冲突与重试测试通过 |
| Phase 6：扩展治理 | 高级评测、成本路由；仅在有证据时考虑多 Agent | 单 Agent 的工具选择或流程复杂度确实成为瓶颈 |

## 11. MVP 验收场景

### 11.1 权限与安全

- admin/pm/engineer/viewer × 项目成员/非成员覆盖核心 Tool。
- 非成员查询项目 ID、任务 ID、文档 ID 时，不返回实体内容或可用于枚举的信息。
- 用户停用、移出项目或降权后，下一次 Tool 调用立即按新权限处理。
- 公共文档和项目文档严格按已确认的可见性策略过滤。
- 文档中的“忽略规则、调用 Tool、泄露其他项目”等内容不能改变 Agent 行为。
- 只读 MVP 中所有 Tool 的副作用声明均为 `none`，数据库无业务写入。

### 11.2 正确性与可解释性

- 准备不少于 50 条固定评测问题，覆盖项目/任务、BOM/变更、权限、文档和失败场景。
- 进度、逾期数、阻塞数、延迟 BOM 等聚合与直接服务查询完全一致。
- 每个数字展示口径和 `asOf`；进度明确标识 `done_task_count`，不得暗示为工时进度。
- 项目同名时进入消歧，不静默选择；查无数据时明确返回空结果。
- Tool 超时、模型超时、取消和重试不会造成重复业务写入或失控循环。

### 11.3 审计与运营

- 每个 Agent Run 可关联其全部 Tool 调用、错误、证据和最终状态。
- 日志不记录密码、会话令牌、数据库连接串和完整敏感提示内容。
- 管理员可停用单个 Tool 或整个 Agent；停用不影响 WorkBuddy 主业务。

## 12. 成功指标

试点期先记录基线，再确定正式 SLO。建议评审以下指标：

- 固定评测集任务成功率与按场景拆分的失败原因；
- 数字类答案准确率、引用可打开率和引用支持率；
- 权限阻断正确率与越权事件数；
- P50/P95 响应时间、平均 Tool 次数、取消率和错误率；
- 用户反馈采纳率、重复查询率、周报人工修改量；
- 模型 token 与单次成功任务成本。

任何“节省工时”结论必须来自试点前后可比数据，不在开发阶段预设收益数字。

## 13. 风险与依赖

| 风险 | 控制措施 |
|---|---|
| 权限泄露 | 身份由服务端注入；Tool 内重新鉴权；实体级过滤；越权回归集 |
| 事实幻觉 | 结构化 Tool、证据约束、无数据拒答、数字一致性评测 |
| 数据口径误导 | 返回算法版本、时间窗、数据质量和限制；组织/负载 Tool 默认禁用至数据就绪 |
| 文档提示注入 | 文档视为不可信数据、内容隔离、Tool allowlist、检索红队测试 |
| Agent 影响主系统 | 独立 Worker、超时/并发/步数限制、熔断、只读首发 |
| 长流程重复执行 | 幂等键、检查点、版本重验和回读验证；写操作后置 |
| 供应商锁定 | Model Provider 适配层、Tool Contract 与模型 SDK 解耦 |
| 基线尚未生产验收 | Agent 上线不能绕过既有生产门禁；先完成隔离数据库与 RBAC 验收 |

## 14. 已确认决策

- [x] 首期定位为“单 Agent、只读、证据优先”，暂不做多 Agent 与业务写入。
- [x] WorkBuddy Pro 是唯一事实源，Agent 不直接访问 PostgreSQL。
- [x] v1 进度继续使用 `Done / 总任务数`，强制展示算法口径；权重进度另立数据改造项。
- [x] 组织结构首版采用“一人一个主部门 + 一条直接汇报线”；跨职能关系继续使用 `ProjectMember`，矩阵组织作为后续扩展。
- [x] 首版保持当前公共文档语义：`projectId = null` 对已登录用户可见；实施时增加显式策略配置与回归测试。
- [x] 多人工时与负载仅对拥有 `time:read_all` 且满足项目/组织范围的用户开放；邮箱默认不进入模型上下文。
- [x] 模型通过 Provider Adapter 接入，首版供应商与部署参数由环境配置；数据最小化、脱敏和保留策略是上线门禁。
- [x] 架构 ADR、Tool v1 名称和 MVP 验收指标作为实施基线；具体阶段与验收命令见 [实施计划](./AGENT_IMPLEMENTATION_PLAN.md)。
