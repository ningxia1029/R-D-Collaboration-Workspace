# Agent 事故响应手册

## 1. 分级

- P0：确认或疑似越权数据泄露、未经确认写入、密钥泄露、审计缺失。
- P1：大面积模型/Worker 故障、错误回答影响决策、成本异常、恢复失败。
- P2：单个 Run 失败、非关键 Tool 降级、局部性能退化。

## 2. 十五分钟内动作

1. 记录事故编号、发现时间、用户、Run/trace/correlation、受影响项目与版本。
2. P0/P1 立即关闭 Agent 总开关；必要时同时停用具体 Tool。
3. 保留 AgentRun、ToolExecution、审批、AuditLog、ActivityEvent 和部署日志；不得先清理证据。
4. 密钥疑似泄露时轮换对应密钥并撤销旧 Worker；不在聊天或工单粘贴秘密值。
5. 检查是否存在真实业务写入；Action proposal 与执行必须分别计数。

## 3. 专项处置

### 提示注入

隔离来源文档，保留原版本与 chunk 哈希；确认攻击内容未改变身份、Tool allowlist 或执行路径；重新索引前由业务负责人复核。

### 未确认写入或越权

保持总开关关闭；按 `executionIdempotencyKey`、审批 ID 和业务 AuditLog 串联；冻结相关账号/token；由业务负责人决定业务数据回退，禁止 Agent 自动反向修改。

### 模型异常或成本激增

停用 Provider/模型，检查 token、Run 步数、Tool 次数与预算；切换模型必须按模型切换手册重新评测。

## 4. 恢复条件

根因、影响面、数据修复、密钥轮换和防复发测试均有证据；固定评测、RBAC、未确认写入、浏览器与审计门禁重跑通过；由事故负责人和项目负责人共同批准恢复。
